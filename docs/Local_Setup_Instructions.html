Workshop Registration Service

Local setup instructions — running the frontend and the backend on your machine

Stack: NestJS 12 + Prisma 6 + PostgreSQL (API)  |  Next.js 16 (React 19) + plain CSS (UI)  |  Verified on: macOS, Node v22.17.0, npm 11.5.2

Everything below is copy-paste. Run the steps in order and you will have the API on http://localhost:3001, the UI on http://localhost:3000, three working logins and four sample workshops — no hosted database required.

3. Step 1 — get the code

git clone <repository-url> workshop_registration
cd workshop_registration

Two separate package.json files — one per app — so install and run each folder on its own. Use two terminals (or two terminal tabs): one for the API, one for the UI.

4. Step 2 — a PostgreSQL database

Pick the line that matches your machine. All three produce the same DATABASE_URL shape.

Option A — PostgreSQL already installed (Homebrew on macOS)

brew services start postgresql@16
createdb workshop_registration
# DATABASE_URL: postgresql://<your-macos-username>@localhost:5432/workshop_registration

Homebrew's Postgres trusts local connections and sets no password by default, so the username is simply whoever you are (whoami). On Linux use sudo -u postgres createdb workshop_registration.

Option B — Docker (nothing to install, disposable)

docker run --name wr-postgres -e POSTGRES_PASSWORD=postgres -p 5433:5432 -d postgres:16
docker exec wr-postgres createdb -U postgres workshop_registration
# DATABASE_URL: postgresql://postgres:postgres@localhost:5433/workshop_registration
# Stop it with: docker stop wr-postgres   (start again: docker start wr-postgres)

Option C — a free Neon Postgres (same engine as the live deployment)

Create a project at neon.com, click Connect and copy both connection strings: the pooled one goes into DATABASE_URL, the direct (unpooled) one into DIRECT_URL, because migrations cannot run through the pooler. Keep the ?sslmode=require the dashboard adds and append &connect_timeout=15 — Neon suspends idle computes and without it the first query can fail with "Can't reach database server".

Only the database name is created here. The tables come from the migrations in step 4 — you do not need to write any SQL by hand.

5. Step 3 — install the backend and point it at the database

cd backend
npm install            # NestJS, Prisma, bcrypt, vitest, oxlint
npx prisma generate    # generates the typed Prisma client into node_modules

Create backend/.env — the file is git-ignored, so real credentials never reach the repository:

DATABASE_URL="postgresql://postgres@localhost:5432/workshop_registration"
DIRECT_URL="postgresql://postgres@localhost:5432/workshop_registration"
JWT_SECRET="change-me-to-a-long-random-string"
PORT=3001
# CORS_ORIGIN="http://localhost:3000,https://your-site.netlify.app"   # only to lock CORS down
VariableRequired?What it does
DATABASE_URLYesRuntime connection string used by Prisma Client.
DIRECT_URLYes*Unpooled connection used by migrations. Locally set it to the same value as DATABASE_URL.
JWT_SECRETRecommendedSigns and verifies the login tokens. Without it the API falls back to a development-only constant — acceptable locally, but a deployment must set it, otherwise anyone holding the source can forge an ADMIN token.
PORTNoDefaults to 3001.
CORS_ORIGINNoComma-separated allow-list. Empty means CORS is open, which is what you want for local work and for any *.netlify.app preview URL.
Signed in yesterday and now every request is 401? JWT_SECRET changed (or was added), so old tokens no longer verify. Sign out and sign in again — nothing is broken.

6. Step 4 — create the tables and load the demo data

npx prisma migrate deploy    # applies the committed migrations (creates all tables)
npm run db:seed              # 3 logins + 4 sample workshops

The seed prints what it created and is safe to run repeatedly: users are upserted without resetting an existing password, and registrations are only inserted into workshops that have none, so your own test data is never wiped.

7. Step 5 — run the backend API

cd backend
npm run start:dev      # watch mode, restarts on save  ->  http://localhost:3001

For a production-style run instead: npm run build && npm run start:prod.

Confirm it is up before moving on:

curl http://localhost:3001/health
# {"status":"ok"}
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3001/users
# 401  - the request had no token, which is the correct answer

The API surface, and which role each route accepts:

EndpointAllowed rolesPurpose
POST /auth/loginpublicReturns the JWT, the role and the email.
GET /healthpublicLiveness probe for hosting platforms.
POST /usersADMINCreate an account and set its role. There is no public signup.
GET /usersADMINList accounts.
GET /users/auditADMIN, MANAGER, STAFFAudit trail (who did what, when).
GET /workshopsMANAGER, STAFFCatalogue plus the active/seat counts used by the filters.
GET /workshops/:idMANAGER, STAFFOne workshop with its full registration history.
POST /workshopsMANAGERAdd a workshop (409 if the code is already used).
PATCH /workshops/:idMANAGEREdit a workshop (title, instructor, date, capacity, status).
POST /registrationsMANAGER, STAFFRegister an attendee — ACTIVE, or WAITLISTED when the workshop is full.
PATCH /registrations/:id/cancelMANAGER, STAFFCancel, keep the row, and promote the next waitlisted attendee.
An ADMIN token cannot list workshops (403) — by design, from the roles table in the brief. Browse the catalogue as manager@test.com or staff@test.com.

8. Step 6 — run the frontend

cd ../frontend          # from the repository root: cd frontend
npm install
npm run dev             # -> http://localhost:3000

Create frontend/.env.local to tell the UI where the API lives:

NEXT_PUBLIC_API_URL=http://localhost:3001
SituationWhat to do
Local development.env.local is optional — the code already falls back to http://localhost:3001.
Local production buildSet it if the API is on another port or host, then npm run build.
NetlifyMandatory. The value is baked into the bundle at build time, so a build without it produces a site that only talks to your own laptop. next.config.ts therefore fails the Netlify build with a clear message when the variable is missing or still points at localhost.

9. Step 7 — sign in and try it out

Open http://localhost:3000, sign in with one of the seeded accounts, and use the sidebar to switch views. The email is the only thing that changes what you can see.

EmailPasswordRoleWhat you can do
admin@test.comadmin123ADMINCreate accounts and assign roles; read the audit trail.
manager@test.commanager123MANAGERAdd and edit workshops, register and cancel attendees, see history.
staff@test.comstaff123STAFFRegister and cancel attendees, see history.

Five-minute click-through that exercises every requirement:

  1. Sign in as staff — the workshops list loads with seat counters and no user-management menu.
  2. Overview — type a date range, or filter by status, or tick "seats available" only. That is requirement 4.
  3. Workshops → FIT-301 (Morning Fitness) — it shows 4/4 seats. Register an attendee: the response is a waitlist row, not an error, and the seat count does not move.
  4. Cancel one of the active registrations on that same workshop. The cancelled row stays in the history with your email and the time, and the person from step 3 is promoted to ACTIVE in the same instant the seat frees.
  5. Sign in as manager — add a workshop, then edit its capacity. Try the same code twice to see the 409 message.
  6. Sign in as admin — create a user with any role, then open Activity to see the trail: account creation, workshop edits and cancellations, each with the actor and a timestamp.

11. If something does not work

SymptomCause and fix
The login page says "Unable to reach the server"The API is not running, or the UI is pointed elsewhere. Check curl http://localhost:3001/health; if that works, fix NEXT_PUBLIC_API_URL in frontend/.env.local and restart npm run dev (Next.js inlines the value at build/start time).
Can't reach database server / Prisma P1001Postgres is not running or the URL is wrong. brew services list, docker ps, or try psql "$DATABASE_URL". For Neon, add &connect_timeout=15 — the first connection after the compute wakes can take a few seconds.
Environment variable not found: DATABASE_URLbackend/.env is missing or in the wrong folder. It must sit next to backend/package.json.
TypeScript cannot find @prisma/clientRun npx prisma generate (step 3). It must be repeated after changing schema.prisma.
EADDRINUSE on 3000 or 3001Something already owns the port. lsof -ti:3001 | xargs kill, or use another one: PORT=3002 npm run start:dev and the matching NEXT_PUBLIC_API_URL.
401 Invalid signature right after signing inTwo servers with different JWT_SECRET values, or the secret changed under a live token. Restart the API with one secret and sign in again.
400 with "property X should not exist"The API rejects unknown body fields on purpose. Send only the fields the endpoint documents.
Registration answered WAITLISTED instead of ACTIVENot a bug: the workshop is full. Cancel an active registration and the first person in the queue (oldest first) is promoted automatically.
Nothing appears in the Activity viewExpected on a brand-new database — the list fills as soon as you create a user, edit a workshop, register or cancel. npm run db:seed also writes a few entries.
